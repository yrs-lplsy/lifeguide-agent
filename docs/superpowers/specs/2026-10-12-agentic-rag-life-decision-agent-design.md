## 2. 用户与场景

**目标用户**：面对具体生活决策的普通人（"被裁了先做什么""替朋友担保签不签""35 岁该查什么"）。

**场景一：决策问诊（主场景）**
用户描述处境 → Agent 追问关键变量 → 检索条目 → 按成本/收益/证据等级排序输出建议，每条带【第 X 节第 Y 条·证据 A】角标。

**场景二：个人自查清单（副场景）**
Agent 通过 3-5 轮问答建立画像 → 批量检索画像相关主题 → 生成按性价比排序的个性化行动清单（可勾选、可导出），持续跟踪完成状态。

两场景共享检索层、记忆体系与用户体系，工作流不同——展示 Agentic 编排能力。

## 4. 离线数据管线（项目护城河）

### 4.1 条目解析器

`book/*.md` + `docs/*.md` → 结构化 JSON（每条目一条记录）：

```json
{
  "section_no": 1, "item_no": 3,
  "title": "装烟雾报警器；冬天室内烧煤/燃气取暖的再装一氧化碳报警器",
  "cost": "烟雾报警器 30-100 元…",
  "benefit_plain": "说人话"栏全文,
  "benefit_detail": "收益"栏全文（含 OR/CI 等统计值）,
  "evidence_level": "B",
  "sources": [{"text": "Marshall SW 等 (1998)…", "url": "https://doi.org/..."}],
  "note": "备注栏全文（适用条件/例外）",
  "cost_tags": {"钱": "少", "时间": "少", "毅力": "否", "收益": "大", "口径": "死亡率"},
  "topic": ["家庭安全", "火灾"],
  "full_text": "整条原文"
}
```

解析规则：以 `### N. 标题` 为条目边界；`- 成本：/- 说人话：/- 收益：/- 证据等级：/- 来源：/- 备注：` 字段行定位；HTML 注释 `<!-- 成本标签: … -->` 解析为 cost_tags（键值按 `=` split）。**容错要求**：34 章全部解析成功、条目总数与 README 声称的 687 一致（±5 容差，差异输出报告）、字段缺失时置 null 而非报错。docs/ 长文无固定结构，按标题层级切块，`evidence_level=null`。

### 4.2 父子 Chunk

- **子块**：条目内按字段切（成本/说人话/收益/备注各一块），256-512 token，用于精确检索
- **父块**：完整条目，回答时回填——**保证备注栏的适用条件不丢**（原书 SKILL.md 明确警告"只读标题会把条件丢掉"）
- chunk 元数据携带：`{section_no, item_no, evidence_level, cost_tags, topic, field_name}`

### 4.3 三级索引

| 存储 | 内容 | 用途 |
|---|---|---|
| Milvus | bge-m3 稠密向量 + 稀疏向量（每子块） | 语义召回 + 术语加权 |
| PostgreSQL tsvector | 子块全文 BM25（标题/来源字段加权 boost） | 政策名、法条号、数字精确匹配 |
| PostgreSQL JSONB | 条目原始结构化记录（source of truth） | 回填、溯源、清单勾选状态 |

## 5. 检索设计

1. **三路召回**：BM25（精确词）+ bge-m3 稠密（口语问句）+ bge-m3 稀疏（术语），各取 top-20
2. **RRF 融合**（免权重调参），再 bge-reranker 精排取 top-5 父块
3. **查询改写**：多轮指代消解 + LLM 生成 2-3 个扩展 query（口语化输入信息不全，改写质量决定召回）
4. **元数据过滤/排序即产品功能**：支持 `evidence_level ∈ {A,B}` 过滤、按「证据等级 > 收益量级 > 成本」排序——维度来自语料自带的 cost_tags，不是硬编
5. **零命中处理**：如实告知"书里没写"，可给常识判断但必须标注非书中内容（原书 SKILL.md 协议）

## 6. Agent 工作流（LangGraph）

### 6.1 决策问诊流

```
输入 → [安全分类] ─高危→ [优先响应链]（模板+120/12356/律师指引，不进 LLM）
         │正常
         ▼
    [意图/变量判断]（LLM 结构化输出 JSON：missing_variables[]）
         │缺变量──→ [追问] ←─ 用户补充
         ▼齐
    [查询改写+扩展]
         ▼
    [检索工具] ←─ 循环：首轮结果不足（相关度低于阈值）→ 改写再检，最多 2 次
         ▼
    [综合排序回答]：按证据>收益>成本排建议，每条带【第X节第Y条·证据A】角标
         ▼
    [引用白名单校验]：回答中每个条号 ∈ 本轮检索结果集，否则重生成（防幻觉硬约束）
```

状态转移由 LLM 结构化输出（JSON schema 约束）驱动；追问最多 2 轮、检索循环最多 2 次（防止成本失控和体验拖沓）。

### 6.2 自查清单流

```
[画像收集]（3-5 轮结构化问答：年龄段/家庭/住房/职业/健康状况/已有习惯）
  → [批量主题检索]（并行调用检索工具，覆盖画像相关主题）
  → [缺口分析]（对照画像判断：已做到/没做到/不适用）
  → [清单生成]：按性价比排序的「建议做的 N 件事」，可勾选/导出，状态回写用户画像
```

## 7. 用户体系、数据隔离与记忆

### 7.1 用户体系

- **认证**：邮箱注册 + 密码（bcrypt）；JWT access 15min + refresh 7d（httpOnly cookie，刷新轮换）；**游客模式**免注册体验（匿名会话仅存 Redis，TTL 24h 过期即焚），注册后才持久化到 PG
- **数据隔离**：所有业务表（`users / sessions / messages / user_profile / feedback / checklists`）带 `user_id` 外键；API 层从 JWT 解析身份，客户端不传 user_id；管理接口独立 admin 角色。单库行级隔离，面试可讲升级路径（PG RLS / 分库）

### 7.2 长短期记忆

| 层 | 内容 | 存储 | 生命周期 |
|---|---|---|---|
| 短期记忆 | 会话最近 N 轮原文 + 更早轮次 LLM 压缩摘要（token 窗口控制） | Redis + PG | 会话内 |
| 长期记忆 | 结构化画像（年龄段/家庭/住房/职业/健康/习惯）+ **687 条目完成状态**（已做到/没做到/不适用） | PostgreSQL `user_profile` | 跨会话永久 |

- **设计决策：长期记忆用结构化画像而非 Mem0 式向量记忆库**——领域封闭（687 条可枚举），「用户对第 14 条已做到」是精确状态，向量回忆反而引入错误。此 trade-off 为面试重点素材
- **写入流程**：会话结束 → LLM 增量提取画像变化 → JSON schema 校验 → 合并入库；下次会话开场自动注入，两场景共享
- **隐私**：健康/法律对话敏感——提供「导出我的数据 / 删除账户及全部数据」（GDPR 式自清理）；用户数据永不进入检索语料库

## 8. 前端设计与 SSE 协议

技术：React 18 + Vite + TypeScript + TailwindCSS（CookHero 同栈）。

### 8.1 SSE 事件协议

上行：REST POST `/chat`（消息）+ query param `Last-Event-ID` 断连续传；下行：SSE 流。

| 事件 | payload 要点 | 前端呈现 |
|---|---|---|
| `thinking` | Agent 当前判断文本 | 折叠式思考面板流式显示 |
| `retrieval_start` | query 列表 | 检索卡片骨架 |
| `retrieval_hit` | 条目标题/相似度/证据等级/节条号/来源 | 卡片逐条填充，**A/B/C 证据徽章** |
| `tool_call` | 工具名/入参摘要/耗时 | 调用时间线 |
| `answer_delta` | 文本增量 | 打字机输出 |
| `citation` | 条号/标题/DOI/原文锚点 | 角标 + hover 出处卡 + 侧栏原文 |
| `safety_redirect` | 类别/指引 | 高危拦截卡（"请先拨打 120…"） |
| `clarify` | 追问文本 | 追问气泡 |
| `checklist` | 清单条目数组 | 清单组件（勾选/导出） |
| `done` / `error` | trace_id / 错误码 | 结束态 |

**核心原则：用户看到的"思考过程"是真实状态机事件，不是装饰动画**（与 CookHero 共鸣的最大卖点）。

### 8.2 页面

① 对话页（双场景共用，清单场景末尾渲染清单组件）② 溯源侧栏 ③ 会话历史 ④ 反馈组件（👍/👎 + 原因标签）⑤ 极简落地页（项目介绍 + 演示 GIF）。

## 9. 评测体系

1. **Golden Set**：~200 条「问题→应命中条目」，LLM 从条目反向生成 + 人工校验；覆盖三类：口语化改写、跨节多跳（"刚确诊糖尿病注意什么"跨 16/24/34 节）、零命中（书里没有的，测"承认不知道"）
2. **检索指标**：Recall@5 / MRR / nDCG@10，四组消融：纯向量 → +BM25 → +RRF → +rerank，**每加一层出一次数字**
3. **生成指标**：RAGAS（faithfulness / answer_relevancy / context_precision）+ **引用准确率**（回答条号通过白名单校验的比率，本项目特有幻觉硬指标）
4. **在线闭环**：👍/👎 落库周报；Langfuse 全链路 trace（每步延迟/token/命中数）
5. **CI**：评测脚本进 GitHub Actions，指标回归超阈值（如 Recall@5 降 >2pct）报警

## 10. 安全设计（网安背景差异化）

| 层 | 措施 |
|---|---|
| 输入-前置 | 规则+小模型分级分类器：急症/自杀念头/进行中法律程序 → **短路优先响应模板**（120/12356/找律师），不进 LLM、不排队检索——真实安全需求非表演护栏 |
| 输入-注入 | 用户输入注入模式检测；**检索语料视为不可信输入**（分隔标记 + 指令隔离，防书内文本携带诱导指令） |
| 输出 | 引用条号白名单校验；医疗/法律场景免责声明模板 |
| 传输/会话 | HTTPS（nginx + Let's Encrypt）；JWT 过期/刷新轮换；httpOnly cookie |
| 限流 | Redis 令牌桶，按用户 + IP 双维度 |
| 审计 | 记录"谁在何时问了什么**类别**"（不记原文，隐私平衡）+ 安全拦截事件全量日志 |
| 工程 | CORS 白名单、pip-audit 依赖扫描进 CI、密钥用环境变量不进仓库 |

## 14. 明确不做（Scope 外）

- 不做移动端 App / 小程序（Web 响应式即可）
- 不做多语言（语料 translations 由第三方维护，质量不可控；仅中文）
- 不做用户间社交/分享功能
- 不微调模型（API + 检索优化足够；如被问及，答"评估过 LoRA 微调，687 条结构化语料下 RAG 溯源比微调可控"）
- GraphRAG、MCP 仅作为可选实验，不进主线交付承诺
